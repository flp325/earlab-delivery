# EarLab 代码审查问题清单（2026-10-23 · A6c）

审查方式：4 路并行只读审查（引擎/DSP、UI、插件、测试与构建）+ 主审逐条复核；运行三套测试二进制。
范围：`app/src`、`app/tests`、`scripts`、`CMakeLists.txt`、`PRD-v0.3.md`。
**本次未改动任何代码。**

## 结论

功能链路（素材 → 等响 → 干湿切换 → 出题 → 评分 → 存档）是通的，但有三类问题必须先处理：

1. **并发**：UI 线程会直接对音频线程正在渲染的处理器做离线测量，插件场景下可能崩。
2. **训练有效性**：插件幅度题的正确答案直接显示在界面上，不用听就能选对。
3. **可信度**：一键构建实际只跑 47 项断言（文档写 72），插件宿主的关键路径没有自动回归。

建议顺序：批次 1 → 批次 2 → A7 安装包；批次 3 随版本推进。

## 已核查、不计为缺陷

- 音频回调本体（`AudioEngine.cpp:270-355`）无堆分配、锁、文件 IO、异常、日志；FIFO 是标准 SPSC 用法。
- `LoudnessMeter` 的 48 kHz 标准系数与 gating 正确；`CompressorProcessor` 的 knee/attack/release/ratio 正确。
- 扫描子进程/Job 的各条错误路径无句柄泄漏；并行聚合无写竞争。
- 测试不写真实 `%APPDATA%\EarLab`，不污染用户存档。
- CMake 已通过 `juce_recommended_warning_flags` 带 `/W4`（无 `/WX`）。
- JUCE 8.0.15 与 `BUILD.md`、`fetch_juce.py` 一致。
