## 3. 产品定义

**一句话**：一个能加载你自己 VST 的听力训练工作站，用你自己的素材出题，并把你"听不出来"的地方量化成 JND 指标。

三条不可妥协的产品原则：

1. **插件即出题器**：内置套件保证零配置可用，第三方插件保证可迁移性；两者缺一，产品都会退化。
2. **等响即生命线**：任何一道题都必须等响，否则测量的是响度差，不是耳朵。
3. **能力即可迁移**：报告要能回答"我在 2 kHz 处能分辨 1.1 dB"，而不是"今天答对 8/10"。

### 5.4 素材—题型适配矩阵（关键设计）

压缩类训练的听辨难度与素材强相关：attack 在鼓上明显、在人声上几乎听不出。因此**不允许自由组合，必须按矩阵出题**。

| 素材类型 | 适合 | 不适合 / 会误导 |
|---|---|---|
| 鼓循环、单鼓 | attack/release、瞬态、压缩量 | 高频 Q 精细定位 |
| 人声（干声） | 1–8 kHz 频段、去齿音、压缩量 | 低频 Q |
| 贝斯 / 808 | 低频 Q、压缩量、低频堆积 | attack 细微差异 |
| 钢琴 / 弦乐 | 架式、频段、混响 | 强压缩辨识 |
| 完整混音 | 整体平衡、参考匹配 | 单参数精细辨识 |
| 粉噪 / 扫频 | 设备与房间校准、纯频段 | 音乐性判断 |
| 合成器 Pad | Q / 滤波、宽度 | 瞬态类 |

实现为 `stimulus_fitness` 表：`(material_id, skill_id, weight, min_difficulty, max_difficulty)`，出题器按权重采样。

### 5.5 插件系统

**内置套件（默认可用，优先级最高）**

| 插件 | 关键参数 | 覆盖技能 |
|---|---|---|
| EarLab EQ | 8 段贝尔 + 2 段架式 + HP/LP（12/24 dB/oct）；freq 20 Hz–20 kHz（对数）、gain ±24 dB、Q 0.1–18；含实时频谱与单段试听 | 频段定位、增益量、Q、架式/峰值、滤波截止、多段 |
| EarLab Comp | threshold −60–0 dB、ratio 1:1–20:1、attack 0.1–100 ms、release 10–2000 ms、knee 0–24 dB、makeup、mix；GR 表 | 压缩量、攻击/释放、比率、阈值、拐点、过压缩、并行 |
| EarLab Gain | 增益 ±24 dB、声像、相位反转、单声道折叠 | 等响校准、增益分级、相位、ABX 基线 |

内置插件与第三方插件共用同一套处理器抽象，训练引擎不区分来源：

```cpp
struct ITrainableProcessor {
  std::vector<Axis> describeAxes();      // 语义轴：freq / gain / q / attack / ...
  void setAxis(AxisId id, double value);
  std::vector<uint8_t> getState();       // 题目复现
  int getLatencySamples();
  void prepare(double sampleRate, int blockSize);
  void process(AudioBuffer& buffer);
};
```

内置实现直接给出语义轴，映射成本为零；第三方实现经映射库 / 向导填充同一接口。因此**内置插件既是训练引擎的参考实现，也是第三方映射的校准基准**——先用内置插件建立能力基线，再切到用户自己的插件验证迁移。

同一份 DSP 代码可选择额外导出为 VST3，供用户在 DAW 里使用（1.1 的增值点，不阻塞 MVP）。

**扫描**

| 项 | 规格 |
|---|---|
| VST3 路径 | `C:\Program Files\Common Files\VST3`、`%LOCALAPPDATA%\Programs\Common\VST3`、用户自定义目录 |
| 浅扫 | 枚举 `.vst3` 目录与 `Contents\x86_64-win\*.vst3`，读元数据 + 文件指纹（size/mtime/SHA-256 前 1 MB），秒级 |
| 深扫 | 子进程实例化，`IComponent` 加载 → 枚举参数 → 记录延迟/IO → 销毁；单插件 8 s 超时 |
| 失败处理 | 超时或崩溃 → 标记 `timeout` / `crash`，进入隔离名单，可手动重试，**不阻塞其余插件** |
| 增量 | 指纹未变则跳过；下次启动只处理变更 |
| 只读原则 | 不修改插件文件、不写入插件目录、不上传任何插件信息 |

**兼容性分级**

| 等级 | 定义 | 用户体验 |
|---|---|---|
| A 完全支持 | 参数可枚举且语义映射成功 | 可出全部题型 |
| B 可加载 | 参数可枚举但语义未映射 | 只出"参数 A→B 变化辨识"题 |
| C 不支持 | 崩溃、超时、无参数、需要 GUI 授权 | 隔离，给出原因与建议 |

**参数语义映射（三种来源，按优先级）**

1. **内置映射库**：Top 40 常用插件人工标注（Pro-Q 3/4、Pro-C 2、SSL Channel、Kickstart、Valhalla、Decapitator 等），随版本更新，以 JSON 补丁包形式分发。
2. **启发式推断**：读取 VST3 `ParameterInfo`（title / units / stepCount / defaultNormalized），按单位（Hz、dB、ms、%）与命名模式（`Band 2 Freq`、`Ratio`）推断语义轴。
3. **手动映射向导**：软件列出候选参数，用户拖动一个参数并标记"这是频段 2 的频率"，生成用户级映射（可导出分享给社区）。

**其他**

- 插件状态快照：`IComponent::getState()` 二进制保存，用于题目复现与分享题单。
- 插件链：MVP 支持 1 个插件、最多 2 个实例（干 / 湿并行）；P1 支持 3 个串联。
- 插件 GUI：以独立原生顶层窗口承载，**不嵌入 Electron 画布**（避免 DPI、输入法、层级、模态问题）。

## 6. 技术规格

### 6.1 进程与通信

```
┌──────────────── UI 进程（Electron + React + TS）────────────────┐
│ 训练台 │ 技能树 │ 插件管理器 │ 素材库 │ 报告 │ 设置              │
└──────────┬──────────────────────────────┬─────────────────────┘
           │ IPC：protobuf over named pipe │ SQLite（WAL，主进程持有）
┌──────────▼──────────────────┐   ┌───────▼─────────────────────┐
│ 音频引擎进程（C++ / JUCE）    │   │ 扫描器进程（独立，可崩）      │
│ 设备：ASIO / WASAPI          │   │ 枚举 · 指纹 · 超时 · 隔离     │
│ 图：源 → 插件链 → 响度 → 输出 │◄──┤ 结果写入 SQLite（只读句柄）   │
│ 双链并行 + PDC + 交叉淡化     │   └─────────────────────────────┘
│ 分析：LUFS / 频谱 / 相关度    │
└──────────────────────────────┘
```

- 音频数据不跨进程：引擎直接读素材文件并输出到声卡。
- UI 只收控制消息与低频可视化数据（波形包络 30 Hz、频谱 30 Hz）。
- 引擎心跳：UI 3 s 未收到心跳则判定挂起，杀掉并重启引擎，恢复上次会话（题目与作答不丢）。

### 6.2 音频引擎硬性要求

| 要求 | 规格 |
|---|---|
| 实时线程 | 零内存分配、零锁、零 JSON 解析、零日志 I/O |
| 等响 | 干湿两路各自做 ITU-R BS.1770-4 积分响度归一至 -23 LUFS，再叠加 ±0.3 dB 随机抖动 |
| 延迟补偿 | 插件 `getLatencySamples()` 整数延迟 + 分数延迟线性插值，干路对齐湿路 |
| 交叉淡化 | 等功率，10–20 ms，两路常驻并行（不 bypass 插件） |
| 采样率 | 固定 48 kHz（插件行为最稳），可选 44.1 / 96 |
| 性能 | 256 samples @ 48 kHz，单插件链 CPU < 8%，连续 4 小时零 xrun |
| 设备 | ASIO 优先，WASAPI 共享模式兜底；设备热插拔重连 |

### 6.3 扫描器硬性要求

- 独立进程，Windows Job Object 限制（`KILL_ON_JOB_CLOSE`）+ 内存上限 2 GB
- 单插件 8 s 超时，超时强杀并记录
- 扫描期间不弹任何 UI 窗口；需要 GUI 授权的插件在深扫中标记 `needs_gui` 并跳过
- 断点续扫：崩溃后从上次进度继续
- 结果幂等：同一指纹的扫描结论缓存，跨版本失效重扫

### 6.4 自适应与评分

- **阈值估计**：2-down-1-up 阶梯法，收敛至 70.7% 正确率；每技能 20–40 trial，bootstrap 置信区间
- **能力值**：每技能一个 θ，题目难度 d 由物理量映射（dB 与频率取对数刻度），`P = logistic(θ − d)`，Elo 式更新 K=16
- **题目校准**：新题初始难度由设计者给定，累计 30 次作答后按实际正确率修正
- **复习排期**：FSRS（简化版），错题与临界题优先
- **反应时**：作为次要指标记录，用于区分"听出来但答错"与"没听出来"

### 6.8 故障处理策略

| 故障 | 行为 | 用户可见 |
|---|---|---|
| 插件扫描崩溃 | 隔离该插件，记录崩溃码，继续扫其他插件 | 插件列表标红 + "为什么不可用" |
| 插件扫描超时 | 标记 `timeout`，允许手动重试 | 黄色标记 + 重试按钮 |
| 运行中插件崩溃 | 引擎捕获，重置该插件实例，会话继续 | 顶部提示"XX 插件已重置" |
| 引擎无响应 | 3 s 心跳超时 → 强杀重启 → 恢复会话 | 2 秒遮罩"正在恢复" |
| 音频设备丢失 | 回退 WASAPI 默认设备 | 提示条 + 设置入口 |
| 等响对齐失败 | 该题不出，重新采样 | 无感（记录进日志） |
| 素材/插件缺失 | 题目作废并重排 | 无感（记录进日志） |

原则：**故障只影响单个插件或单道题，不能影响整个训练会话**；所有降级都要有可见说明，不静默。
